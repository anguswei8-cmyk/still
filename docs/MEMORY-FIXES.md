# 图片内存滞留修复

日期：2026-10-29。针对当前 Qt 实现，保留图标工具栏。

## 修复

- OCR 排队不再通过 QtConcurrent 的 lambda 持有每张待识别原图。等待图片由 OcrJob 自己持有，销毁 job 会从待处理列表移除，并立即释放其图片引用；仅在得到两个并发名额之一时才交给线程池。
- 贴图换图/旋转/重新识别、编辑器重新识别和截图识字均替换旧请求，防止单一所有者积压多个旧版本。已关闭请求不再回调。运行任务的 watcher 不随窗口销毁，完成后仍归还名额并继续后续任务。
- 长截图只有通过屏幕范围和控制条位置检查后才写入首帧，启动失败不残留原图。

系统 OCR 调用仍在原生引擎中执行，不能立即中断；最多两张正在识别的图片会保留到系统调用返回。显示中的图片、编辑器原图和剪贴板图片仍按原功能持有，不属于泄漏。

## 验证

新增五个回归场景：关闭 24 个排队贴图、同一贴图换图 24 次、运行任务关闭后后续任务仍能完成、编辑器连续识别 24 次，以及整屏长截图因控制条无空间而启动失败。测试使用 QImage 清理回调跟踪真正的原图释放，OCR 使用可控阻塞 fixture。

修复前前三类相关失败记录在 `build/memory-regression-before.txt`（关闭、换图、编辑器请求数），长截图失败记录在 `build/scroll-regression-before.txt`；修复后四组 CTest 全部通过，报告为 `build/*-results.txt`。真实 Windows OCR/热键集成测试也通过。

沿用初次审查的 1920×1080 图片探针：

| 场景 | 修复前仍持有的原图 | 修复后仍持有的原图 |
| --- | --- | --- |
| 关闭 24 张贴图，两个 OCR 线程仍阻塞 | 24 张，189.84 MiB | 2 张，15.82 MiB |
| 解除 OCR 阻塞并完成识别 | 0 | 0 |
| 长截图启动被拒绝，Application 仍存活 | 1 张，7.91 MiB | 0 |

数据在 `build/memory-audit/ocr-queue[-fixed].json`、`aborted-scroll[-fixed].json`。100 轮设置/编辑器/遮罩/贴图开关探针中，100 张原图全部释放，每批关闭后均只余常驻托盘菜单；记录在 `lifecycle-fixed.json`。这些探针使用模拟 OCR，图片为合成数据，不是系统识别引擎的长期内存基准。

## 未覆盖

后续历史存储优化已减少长截图的整图格式转换/比较副本，并在输出分配前检查高度和 256 MiB 字节预算，细节见 `HISTORY-STORAGE.md`。拼接仍会同时持有输入、输出，不代表没有临时峰值。未做 Mac 实机、数小时真实 OCR/GPU 压力测试或 ASan/LSan 检测。
