# 架构审查三项修复

日期：2026-10-29。按审查报告顺序完成；没有改截图工具栏或设置页视觉，也未迁移真实用户历史。

## 1. 历史变更

HistoryStore 继续承担文件队列，在同一顺序中处理入库、删除、清空与迁移。清空在此前接受的入库之后执行，之后的新截图仍可入库；删除仅接受当前历史目录里的文件。UI 的确认框只传递意图，文件操作不再绕过队列。

删除确认前先保存文件路径。确认框会运行事件循环，期间后台入库可能刷新并销毁列表项，不能在确认后继续使用该列表项指针。

历史缩略图、编辑和贴图通过 HistoryStore 提供的读图步骤读取，读图与文件变更在模块内部协调。Windows 解码器持有文件时，删除等待该次读取结束；缩略图仍在独立后台线程解码，不把整批解码排入写队列。读图步骤只共享文件访问保护，不持有窗口或 HistoryStore 本身，允许窗口关闭后安全结束当前解码。

回归：入库→清空最终为空、清空→新入库仅保留新图、入库与单文件删除交错、拒删历史目录外的手动图片、确认框内刷新列表、缩略图读取后可立即删除。完整设置生命周期连续三轮通过。

## 2. 设置应用

SettingsApply 持有唯一的已提交设置，并协调热键与历史选项。设置窗口仅收集输入与展示进度/结果；关闭窗口不取消已经接受的保存。

Hotkeys 的公共逻辑在 hotkeys.cpp，Win32 / Carbon / 测试替身只实现注册和释放。保存前预留可用的新键，保留旧键注册；预留键不会派发动作。单键冲突保留该项旧值，其他修改仍可提交。

HistoryStore 只接收历史选项及一个提交步骤：复制校验成功后，由 SettingsApply 提供的值捕获步骤原子写配置；成功再清理源图。HistoryStore 不知道全部应用设置。成功回调后切换预留键与内存设置，失败只释放预留，不做旧键的释放/重新抢占。

回归：保存期间旧键保持注册、新键仅预留而不触发、提交失败仍持有旧键、单键冲突的部分成功、保存过程中关闭窗口。Windows 系统集成测试同时验证旧键/新键的占用与释放。

## 3. 滚动截图会话

ScrollSession 拥有采样定时器、图片、帧数、预算、会话代次和在途拼接；Application 保留 QScreen 抓帧适配、控制条绘制与最终复制/贴图/入库。

停止时只交付一次最后成功图片并丢弃旧结果。旧轮拼接尚未返回时，新轮可以开始，但暂不排入更多拼接，避免连续停止/重启积压大图。关闭旧控制条的连接会在收尾时解除，不会误停下一轮。

回归：达到帧数后正确交付、拼接中停止→旧结果到达→新轮结果正确、在途拼接期间不追加采样、抓帧失败与预算超限保留最后成功图片、重复停止不重复交付。
