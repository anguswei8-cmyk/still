# 历史目录、容量与响应优化

> 旧设计工具的截图、审查记录及局部说明已于 2026-11-12 清理；下文保留当时的验收记录。

日期：2026-10-29。适用 Qt 主实现，保留图标工具栏和已有 OCR 内存修复。

## 使用

打开设置 → 截图历史，在“历史保存目录”选择专用空文件夹，例如 `D:/StillHistory`。选择目录后自动迁移，手动输入则在完成输入后应用，无需保存按钮。迁移和保存均在后台完成；完成前有状态提示。原有默认路径保持兼容，不会擅自选择磁盘或移动真实用户文件。

历史目录独立于“通用偏好 → 默认保存目录”。配置和实例锁仍留在应用数据目录，较大的 PNG 历史使用选择的位置。历史页可关闭自动保留，设置数量和容量上限（默认 200 张、1024 MiB），并显示实际文件数量、占用和生效路径。降低上限自动应用后会清理旧历史。

## 文件与队列约束

- 新目标需为空或有 `.still-history` 标记（兼容旧版 `.pixclone-history`）；拒绝无标记的非空目录和互相嵌套的新旧目录，避免清理无关文件。
- 同一后台队列串行处理图片写入与目录迁移。迁移逐文件复制并校验 SHA-256，保留原修改时间；不同内容的重名文件使用新名字，不覆盖原有内容。
- 删除与清空也进入同一队列。清空会排在此前已接受的写入之后，后续新截图可正常入库；UI 仅确认用户意图，不直接删除文件。
- 复制成功后用 QSaveFile 原子提交配置，随后再次核对并删除旧图片。复制/配置失败仍沿用原目录，原图不会被删除；配置提交失败可能留下已验证的新目录副本，重试可复用。
- 源文件变化或旧副本无法删除时保留源文件并显示提醒。旧目录中的 legacy `history.json` 不改写、不删除。
- 只清理历史目录的 PNG；从最早图片开始，直到数量和实际文件字节数均满足限制。单张编码文件超出容量限制时，在原子提交前取消，不删除已有历史。
- 同一实例中连续相同像素/布局的图片不重复入库；原历史文件已被删除时允许重新保存。
- 后台最多保留 8 张、合计 256 MiB 未压缩图片，包括正在写入的任务。超出预算会提示“本次未加入历史”，复制、贴图、手动保存仍正常；应用退出等待已接受的任务完成。

## 界面与长截图

HistoryStore 在独立读队列中扫描当前历史目录、统计容量并解码图片。缩略图每批解码 50 张，点击“加载更多”继续；刷新或离开历史页会取消过期批次。编辑和贴图的原图也在后台解码，页面隐藏或离开后会丢弃迟到结果。Qt PNG 解码器可能仍需临时读取原尺寸，串行处理避免并发加载多张大图。

历史读图与文件变更由历史模块内部协调，避免 Windows 上正在解码的缩略图占用文件导致删除失败；缩略图解码保留独立后台线程。

滚动匹配对 RGB32 / ARGB32 图片直接采样，不再为累计大图整体转换格式或复制整块比较区域。输出在分配前检查高度与 256 MiB 未压缩预算，超限保留最后成功结果。拼接仍需同时持有输入与输出图片。

## 验证

七组 CTest 覆盖：迁移前后连续写入、迁出再迁回、配置提交失败保留源图、非空目录保护、重名文件不覆盖、禁用历史、数量/容量裁剪、单图超限保护、退出完成队列、过大排队图片拒绝、入库与清空顺序、真实设置界面迁移，以及长截图预算和停止/重开时序。

Windows 合成 2560×1440 PNG 对比中，本轮同一写入函数同步调用约 116–119 ms，后台入队约 0.05–0.12 ms（最新记录见 `build/history-results.txt`；不同设备数值会变化）。原 1920×12000 长截图探针的进程私有提交峰值从约 211.23 MiB 降到 188.38 MiB，释放后约 3.72 MiB；新证据为 `build/memory-audit/scroll-peak-history-fix.json`。

原生设置预览在 `settings-history-content.png` 和 `settings-history-compact.png`。测试及迁移均用临时目录，未替用户移动真实 C 盘历史。尚未做 Mac 实机、真实跨磁盘断电恢复或数小时慢盘压力验收。
